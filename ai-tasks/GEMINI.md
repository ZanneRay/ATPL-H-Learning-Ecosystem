# Task Brief — Gemini / NotebookLM

## Role

Prototype the **source-grounded student media layer** for Module 1. This is a bounded experiment, not permission to generate a replacement textbook.

## Source rule

Use only the source material supplied/approved by the project owner for technical claims. If a claim cannot be supported by those sources, flag it rather than filling the gap from general knowledge.

## Read first

- `docs/curriculum/MODULE-1-BLUEPRINT.md`
- `docs/curriculum/MODULE-1-LEARNING-EXPERIENCE.md`
- `docs/curriculum/MODULE-1-VISUAL-SYSTEM.md`

Use the approved Module 1 textbook/source extracts provided by the owner as the technical source pack.

## Immediate task — pre-study prototype

Target total student preparation: **15–20 minutes**.

Driving problem:

> A helicopter is established in a stable hover. Rotor RPM remains constant. The pilot raises collective. At one blade element, what changes first — and what happens next?

Prepare students to engage with this problem, but **do not reveal the complete causal answer before class**.

Propose:

1. a **6–8 minute visual micro-video** structure;
2. three short prediction/retrieval prompts;
3. likely misconceptions the media should expose without fully resolving;
4. a concise source-grounded student study guide;
5. exact source references for technical statements where the platform supports them.

## Visual constraint

Use the project's approved visual system as the desired technical diagram language. Do not treat automatically generated aerodynamic diagrams as authoritative. The core figures should ultimately come from the controlled visual library defined in `MODULE-1-VISUAL-SYSTEM.md`.

## Second experiment — post-study recap

After the pre-study prototype, propose a short recap using the complete BET reasoning chain:

**velocities → angles → forces → resolved components → rotor output**

The recap should support retrieval/consolidation, not introduce substantial new theory.

## Evaluation

For every generated media format state:

- what learning function it serves;
- what it does better than a static handbook page;
- what technical-quality risks it introduces;
- whether it is worth keeping in the final ecosystem.

The project is not committed to using AI-generated audio/video if it does not add enough educational value.
